## Feature: WFH Day Tracking

### The Problem

The ATO WFH deduction (fixed rate 70c/hour, confirmed by tax agent 2026-04-26) requires evidence of days/hours worked from home. No log was kept for FY2025. The work laptop is a different machine — not this Windows dev machine. Standard router logs are not available (consumer ISP router, no log access).

**ATO compliance note:** The fixed-rate method requires a representative record of hours worked from home — typically a diary or log covering at least 4 representative weeks. The `ctl.wfh_log` table plus a Metabase CSV export constitutes this record. The user must review and confirm the log is accurate before ATO submission. The log itself, with source and confidence columns, provides the audit trail.

### Key Insight

**This Windows dev machine is on every day the user works from home.** If it was active on a weekday, that day = WFH with high confidence. The machine's own Event Log is the signal — no router, no work laptop, no network scan needed.

### Design

#### FY2025 Retrospective (one-time PowerShell script)

Query Windows Event Log using logon events (fires mid-session) and startup events. Pull all weekday events in the FY2025 date range, group by date, and output one row per WFH day.

**Important:** Windows System log default size is ~20 MB. Events from July 2024 may have been overwritten on an active machine. Verify retention before relying on this — see Open Item 2. If fewer than 150 weekday dates are returned (full FY2025 has ~261 weekdays), the log has likely been partially overwritten and the CSV will need manual supplementation.

```powershell
# Script: C:\Users\tosha\Documents\TaxCollector\scripts\build_wfh_log_fy2025.ps1
# Run in an ADMINISTRATOR PowerShell session (required for Security log / Event 4624).
# If admin is unavailable, the Security log query is skipped and only System 6005 is used.
# Queries both System log (Event 6005=startup) and
# Security log (Event 4624=interactive logon) to maximise coverage.
# Groups by date — one CSV row per WFH day.

$startDate = [DateTime]'2024-07-01'
$endDate   = [DateTime]'2025-06-30'

# Collect all candidate events
$events = @()

# System log: startup events (6005 fires at boot time regardless of hour)
try {
    $events += Get-WinEvent -FilterHashtable @{
        LogName   = 'System'
        Id        = 6005
        StartTime = $startDate
        EndTime   = $endDate
    } -ErrorAction Stop | Select-Object TimeCreated, @{N='EventSource';E={'System-6005'}}
} catch { Write-Warning "System log 6005: $_" }

# Security log: interactive logon events (4624 fires when user logs in mid-session)
try {
    $events += Get-WinEvent -FilterHashtable @{
        LogName   = 'Security'
        Id        = 4624
        StartTime = $startDate
        EndTime   = $endDate
    } -ErrorAction Stop |
        Where-Object { $_.Properties[8].Value -eq 2 } |  # LogonType 2 = interactive
        Select-Object TimeCreated, @{N='EventSource';E={'Security-4624'}}
} catch { Write-Warning "Security log 4624 (may need admin): $_" }

if ($events.Count -eq 0) {
    Write-Warning "No events found. Event Log may have been overwritten. Supplement manually."
    exit 1
}

# Group by date — keep weekdays only, one row per date
$wfhDays = $events |
    Where-Object {
        $d = $_.TimeCreated.DayOfWeek
        $d -ne 'Saturday' -and $d -ne 'Sunday'
    } |
    Group-Object { $_.TimeCreated.ToString('yyyy-MM-dd') } |
    Select-Object @{N='date';E={$_.Name}},
                  @{N='wfh_day';E={'TRUE'}},
                  @{N='source';E={'windows_event_log'}},
                  @{N='confidence';E={'HIGH'}},
                  @{N='hours_worked';E={8.0}},
                  @{N='override_note';E={''}}

$outPath = 'C:\Users\tosha\Documents\TaxCollector\wfh_log\wfh_log_FY2025.csv'
New-Item -ItemType Directory -Force -Path (Split-Path $outPath) | Out-Null
$wfhDays | Export-Csv -Path $outPath -NoTypeInformation

Write-Host "WFH log written: $($wfhDays.Count) days to $outPath"
if ($wfhDays.Count -lt 150) {
    Write-Warning "Only $($wfhDays.Count) WFH days found. Expected 150-261 for a full FY. " +
                  "Event Log may be partially overwritten — review and supplement manually."
}
```

Output: `wfh_log_FY2025.csv` (headers: `date,wfh_day,source,confidence,hours_worked,override_note`). User reviews and edits before submission.

**Secondary verification:** See "Bank Commute Flag" below. Days with commute transactions (Opal/Myki, parking, fuel) that appear in the bank data but NOT in the event log output are flagged as potential office days — surfaced in the Metabase dashboard for manual review.

#### FY2026 Onwards (Windows Task Scheduler)

A single daily job at **noon** (12:00 PM Mon–Fri). If the machine is on at noon, mark the day as WFH. Using a single midday job avoids the TOCTOU race condition of two concurrent jobs.

```powershell
# Script: C:\Users\tosha\Documents\TaxCollector\scripts\log_wfh_day.ps1
# Scheduled: daily at 12:00 PM, Mon-Fri only (set in Task Scheduler trigger)
$today   = Get-Date -Format 'yyyy-MM-dd'
$logFile = "C:\Users\tosha\Documents\TaxCollector\wfh_log\wfh_log_FY2026.csv"

# Use a lockfile to prevent concurrent writes (defensive, unlikely with single daily job)
$lock = "$logFile.lock"
$stream = $null
try {
    $stream = [System.IO.File]::Open($lock, 'OpenOrCreate', 'ReadWrite', 'None')
    # Check if today already logged
    $header = 'date,wfh_day,source,confidence,hours_worked,override_note'
    if (-not (Test-Path $logFile)) {
        Set-Content -Path $logFile -Value $header
    }
    if (-not (Get-Content $logFile | Select-String "^$today,")) {
        Add-Content -Path $logFile -Value "$today,TRUE,windows_task_scheduler,HIGH,8.0,"
    }
} finally {
    if ($stream) { $stream.Close(); $stream.Dispose() }
    Remove-Item $lock -ErrorAction SilentlyContinue
}
```

Both scripts produce CSVs with the same header format: `date,wfh_day,source,confidence,hours_worked,override_note`.

#### Bank Commute Flag (secondary verification signal)

Add `is_commute_indicator BOOLEAN DEFAULT FALSE` to `core.bank_transactions`. Set it to `TRUE` in `sp_merge_bank_transactions.sql` when:

```sql
-- In sp_merge_bank_transactions.sql, add to INSERT SELECT:
CASE
    WHEN LOWER(l.transaction_details) LIKE '%opal%'
      OR LOWER(l.transaction_details) LIKE '%myki%'
      OR LOWER(l.merchant_name)       LIKE '%parking%'
      OR LOWER(l.transaction_details) LIKE '%toll%'
      OR (l.nab_category = 'Transport'
          AND l.amount < 0   -- expense, not income
          AND ABS(l.amount) < 50)  -- typical daily commute cost, not a car service
    THEN TRUE
    ELSE FALSE
END AS is_commute_indicator,
```

Surface in Metabase: a query joining `core.bank_transactions` (where `is_commute_indicator = TRUE`) with `ctl.wfh_log` to flag dates with both a commute transaction and a WFH log entry as "confidence: needs review."

#### WFH Ingestion Pipeline

The folder scanner watches `C:\Users\tosha\Documents\TaxCollector\` recursively (confirmed — `extract_folder_tax_docs.py` uses `Path.rglob`). `wfh_log\` is a subfolder within that root. **Check that the scanner's file extension filter includes `.csv`** — it was built for documents (PDF, images) and may need updating.

New pipeline components needed (not yet built):
1. **`prod/scripts/extract_wfh_log.py`** — reads `wfh_log_FY*.csv` files from the watched folder, writes rows to `landing.wfh_log`. Uses watermark: `max(wfh_date)` from `landing.wfh_log` as the load floor (consistent with all other extractors in the project). Batch ID pattern: `BATCH_WFH_{fy_year}_{timestamp}`.
2. **`prod/stored_procedures/sp_merge_wfh_log.sql`** — idempotent UPSERT from `landing.wfh_log` to `ctl.wfh_log`. Deduplicates within the landing batch on `wfh_date` before upserting: `SELECT DISTINCT ON (wfh_date) ... ORDER BY wfh_date, loaded_at DESC`. Uses `ON CONFLICT (wfh_date) DO UPDATE SET source = EXCLUDED.source, confidence = EXCLUDED.confidence, hours_worked = EXCLUDED.hours_worked, override_note = EXCLUDED.override_note, updated_at = NOW()`.
3. **`prod/workflows/LOAD_CORE_WFH_LOG.json`** — n8n workflow following the same pattern as `LOAD_CORE_BANK_TRANSACTIONS`: trigger → Execute Command (run `extract_wfh_log.py`) → Execute SQL (call `sp_merge_wfh_log`). Naming prefix: `TC_LOAD_CORE_WFH_LOG`.

#### Database Schema

```sql
-- landing.wfh_log — raw staging (same pattern as landing.tax_documents)
CREATE TABLE IF NOT EXISTS landing.wfh_log (
    id              SERIAL PRIMARY KEY,
    wfh_date        DATE NOT NULL,
    wfh_day         BOOLEAN NOT NULL DEFAULT TRUE,
    source          VARCHAR(50),
    confidence      VARCHAR(10),
    hours_worked    DECIMAL(4,2) DEFAULT 8.0,
    override_note   TEXT,
    loaded_at       TIMESTAMPTZ DEFAULT NOW(),
    batch_id        VARCHAR(100)  -- pattern: BATCH_WFH_{fy_year}_{timestamp}
);

-- ctl.wfh_log — authoritative WFH day record
CREATE TABLE IF NOT EXISTS ctl.wfh_log (
    id              SERIAL PRIMARY KEY,
    wfh_date        DATE NOT NULL,
    fy_year         SMALLINT NOT NULL GENERATED ALWAYS AS (
                        CASE WHEN EXTRACT(MONTH FROM wfh_date) >= 7
                             THEN CAST(EXTRACT(YEAR FROM wfh_date) AS SMALLINT) + 1
                             ELSE CAST(EXTRACT(YEAR FROM wfh_date) AS SMALLINT)
                        END
                    ) STORED,
    is_wfh          BOOLEAN NOT NULL DEFAULT TRUE,
    source          VARCHAR(50),  -- 'windows_event_log', 'windows_task_scheduler', 'manual'
    confidence      VARCHAR(10),  -- 'HIGH', 'MEDIUM', 'LOW'
    hours_worked    DECIMAL(4,2) DEFAULT 8.0,
    override_note   TEXT,
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    updated_at      TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE(wfh_date)
);
```

#### WFH Deduction Calculation

The view lives in `ctl` schema (not `mart`) to avoid cross-schema referencing from mart to ctl:

```sql
-- ctl.vw_wfh_deduction
-- Lives in ctl (not mart) because it references ctl.wfh_log directly.
-- Metabase is configured to query ctl schema directly for this dashboard tab.
-- ATO fixed rate: 70 cents per hour worked from home (confirmed by tax agent 2026-04-26)
CREATE OR REPLACE VIEW ctl.vw_wfh_deduction AS
SELECT
    fy_year,
    COUNT(*) FILTER (WHERE is_wfh = TRUE)  AS wfh_days,
    SUM(hours_worked) FILTER (WHERE is_wfh = TRUE) AS total_hours,
    ROUND(SUM(hours_worked) FILTER (WHERE is_wfh = TRUE) * 0.70, 2) AS fixed_rate_deduction_aud,
    -- Actual cost method: not yet specced. Remove NULL stub once approach is chosen.
    -- (deferred until accountant advises on method preference)
FROM ctl.wfh_log
GROUP BY fy_year;
```

The Metabase WFH tab queries `ctl.vw_wfh_deduction` directly.

## Feature: Review UI

### Goal

A browser-accessible interface (served locally at 192.168.0.250) where the user can:
1. See all FY2025 documents and their classification
2. Review bank transactions flagged as potentially deductible
3. See WFH days and the calculated deduction
4. Export the accountant handoff report

### Technology Decision

**Metabase (already running at 192.168.0.250)** — build dashboards there. Fast to build, zero new infrastructure.

**Action: "Mark as reviewed"** requires Metabase write-back (Models/Actions feature). This is only available on Metabase Pro+. If the running instance is Community edition, replace with either:
- A DBeaver query the user runs manually (`UPDATE core.tax_documents SET review_status = 'REVIEWED' WHERE id = X`)
- A lightweight n8n HTTP webhook endpoint that accepts a document ID and flips the flag

Confirm Metabase edition before building Tab 1 (see Open Item 5).

**Phase 6 clarification:** "Tax reporter" = validate that Metabase's built-in PDF export of the Summary tab (Tab 4) produces a usable accountant handoff document. If Metabase PDF is insufficient, build a Python script (`prod/scripts/generate_tax_report.py`) that queries `mart.vw_tax_summary` and writes Markdown + PDF via `reportlab` or `weasyprint`.

```
  - Income sources identified
  - Documents still unclassified or unreviewed (list)
  - WFH deduction subtotal
  - Metabase PDF export
```
